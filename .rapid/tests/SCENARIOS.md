# Scenario matrix

Generated by tests/gen-scenarios.sh from each scenario's header; do not edit.
Run: `sh .rapid/tests/run.sh [--fast] [-j N] [FILTER]` (N at once; default RAPID_TEST_JOBS or every scenario at once). Fast subset: marked `fast`.

| Scenario | Fast | Verifies |
|---|---|---|
| banned-and-kept |  | banned files and kept branches, for humans too: pre-commit refuses a staged secret, key, certificate, build output, node_modules, .env, archive or backup on any branch (an .env.example passes, deleting a banned file passes); land and a branch push refuse one committed past the hook. Developers never delete branches: pre-push refuses deleting a branch on the remote by hand while land's deletion passes, and the agent guard denies deleting or renaming dev, main or a branch, preflight or not. |
| batch-close-failed-gates |  | rapid land --failed-gates-only runs again only the gates the previous close of this batch failed: the merges that close verified on their own tree are not verified again, a merge landed since is, and the failed gate of the final tree runs once. With no failed close of the batch on record it is refused by name and runs nothing. The default close runs every gate on every merge, after a failed close too. The close and the doctor print their progress live on stderr: one counted line per merge. |
| batch-close-fixer |  | conf test_on_fail at a close: when the batch gate is the project's scenario run, the command the conf names starts on a failing scenario the moment it fails, with the scenario's name and its kept output; the close fails, pushes nothing and keeps the batch, the fix lands as one more branch and the next close passes without starting the command again. |
| batch-close-marker |  | a close removes only its own marker: the marker of a close under test carries that close's own id. An older close that ends while a newer close holds the batch leaves the newer marker in place, publishes nothing in its name and stops, so the newer close alone answers for the batch. |
| batch-close-one-gate |  | batch-close-one-gate: rapid land runs one gate on the batch's final tree, gates_full, never the |
| batch-close-worktrees |  | the search for the branch that broke a close makes its private work trees one after another: git adds one work tree at a time, so no two of them are ever added at once (a git that reports every overlapping worktree add verifies it), and the search still names the right branch among several. |
| batch-join |  | a branch landing into a batch whose close is testing stops that test: the close exits without pushing and its gate is gone with everything it started, the branch lands, and the next close tests the new final tree and pushes it all; a gate that reads its input finds none; while a close publishes the batch a land refuses, and a marker left by a close that is gone is stale. |
| batch-land-local |  | batch-land-local: a plain rapid land always lands into the open batch: five branches land with no gate run and no push, offline; one rapid land gates the final tree and pushes it all in one push; a close with no batch open says so. |
| batch-land |  | batch landing: rapid land --batch lands each branch exactly as a single land does (its own merge, version tag and test record) but locally and without gates; rapid land gates the final dev tree once and pushes everything in one atomic push. When that gate fails the batch stays: dev, the tags and the branches are kept, the branch that broke the close is named, nothing is pushed (the pre-push guard refuses any push while the batch is open), and rapid land --prune is the rollback. |
| batch-one-push |  | batch-one-push: a batch is exactly one push. Opening a branch pushes nothing, a land pushes nothing, the pre-push guard refuses every push while the batch is open (dev, a landed branch, a new branch), and rapid land sends one atomic push holding dev, the tags, the safety and the vault branches. A failed close keeps the batch and names the branch that broke it among several; the fix lands as one more branch and the next close is the batch's one push. |
| branch-numbers |  | branch numbers: rapid branch names every branch pool/v<series>/n<N>.<kind>.<name>, N one more than any number known, never shared. The number is carried by the branch's safety anchor (safety/v<series>/n<N>.<kind>.<name>), which origin holds once the branch is pushed, so another clone counts past it; offline a clone still writes n<N>, and a branch whose number another clone published first takes the next free number at its land; a closed branch keeps its number in the creation order; a landed merge carries Branch-Number:; a branch made by hand takes the next number at land; a hand-made name reusing a number is refused at land and flagged I7. |
| branch-size | yes | a branch over max_commits is refused before anything changes: its last commit is refused at commit, and made past the hooks the branch is refused by land. |
| check-gate |  | rapid check runs one gate on the work tree and says how it ended: the fast gate by default, the gate --gate names otherwise; "pass" with exit 0, "fail" with exit 1 and the end of the gate's own output, "none" for a gate the conf leaves unset or sets to none. It lands nothing. |
| checked-by-dev |  | a branch is checked by dev's framework, never by its own copy: a branch that rewrites the message rules in its own .rapid still has a bad message refused at commit, at land and at push, by the framework committed on dev, which rapid keeps exported under the git dir for that purpose. |
| cli-usage |  | the CLI's usage contract: rapid -h and --help print the whole usage, opening with the product's positioning (a software development lifecycle tool), and exit 0; no verb and an unknown verb print it and exit 2; a verb's -h prints that verb's lines alone; an argument a verb does not know is refused by name with exit 2 and changes nothing. |
| cli |  | the CLI helps and reports: each verb answers -h with its own usage, status --json reports branch, version and branches, and doctor --fix repairs the hooks setting. |
| commit-audit |  | the deterministic commit audit (the required commit-audit status): commit-msg refuses a subject joined by 'and', 'with', 'plus', 'or', 'then', 'beside', '+' or ',', a [FIX] without Cause: then Fix:, a commit above max_commit_lines and a [NEW] or [FIX] that changes behaviour without touching a test path (the commit after a Red: commit excepted). A smelly commit made past the hook is named by rapid check --audit and --each, refused by land and pre-push, and flagged by I4. The forge's commit-audit job runs rapid check --audit with dev's checker, and under land_pr=required dev's ruleset requires it. |
| concurrent-clones |  | two clones land concurrently: the loser's atomic close push is refused with nothing half-published; land --prune puts its dev back, then sync and land succeed as N+1. |
| fix-names-its-test |  | a [FIX] may name its existing test instead of touching a test path: with real test_paths, a [FIX] that changes behaviour only and carries 'Test: <test path>' naming a test its tree holds commits and lands; one naming a missing file is refused at commit, and made past the hook is refused by land; a [FIX] with neither a test path nor a Test: is refused with the trailer named. |
| gate-log |  | the durable gate log: rapid land stores its one gate's command, exit code, duration and log tail (the value of every TOKEN, SECRET, KEY, PASSWORD or CREDENTIAL variable redacted) as a note on the merge under refs/notes/gates, pushed atomically with dev and the tag; a second clone's land merges origin's notes first, so the ref only grows; rapid doctor --verify shows the stored log beside the rerun; pre-push refuses deleting or rewriting the notes ref, and the agent guard refuses writing, rewriting or deleting it by hand. |
| land-body | yes | merge bodies and requirements say something: land refuses a requirement under three words, a body paragraph under three words and a list without an item of two words, and a body that sets a trailer land writes itself; a body's final paragraph of 'Key: value' lines becomes real trailers. |
| land-closes-batch |  | rapid land lands its branch and closes the open batch: the branches landed with --batch before it stayed local, the close tests the final tree once and one push carries every merge. With no batch open it is a batch of one, through the same path. Run again it redoes nothing: a close origin refused runs again from the landed branch, or from dev, without testing the same tree twice. rapid land --halt stops the close under test and keeps the batch, and says so when no close is under test. |
| land-local | yes | branch, three commits, land with no remote: I1-I4 and I8 hold, exit 0. requirement_test is optional by default: a branch opened with no -r, --test or --ticket stages no requirement file, commits with no placeholder in its way and lands with no Requirement: trailer; a test that is given is checked and recorded. |
| land-rebases | yes | land-rebases: four branches forked from the same dev land in one command (rapid land BRANCH...): land rebases each stale branch onto dev itself behind a preflight ref; the third conflicts with the first, so it is left exactly as it was, named with its conflicting file, land_on_conflict starts on it, and the exit is 4, while the second and the fourth still land. |
| land-remote |  | land with a remote: one atomic push carries dev, the tag and the branch deletion. |
| lazy-docs |  | no lazy commit or requirement: with commit_body at its default and requirement_test=required, a bodiless [FIX] commit is refused at commit and, made past the hook, by land and I4; a subject repeated as the body does not count, a Cause: line then a Fix: line does; the requirement "fix the bug" is refused at land; a Test: naming a file the branch lacks is refused; a stated requirement with its test lands with a Test: trailer, and rapid branch --test writes the line. |
| link-drop |  | the link drops between the merge and the push: nothing changes locally or on origin, and the next land resumes without a duplicate tag. |
| merge-tree-gate | yes | the full gate fails on the merge tree although every branch commit passes the fast gate: dev and the tags stay unchanged. |
| message-rules | yes | commit-msg refusals: each rule refuses with its fix named and the subject help printed once with every tag, nothing is rewritten. |
| no-coauthor |  | no Co-Authored-By trailer of any kind: a commit carrying one is refused at commit and, made past the hook, by land; a hand-made merge of one is flagged I4. |
| no-setup-clone |  | a clone that never ran rapid setup says so: rapid branch, land, sync and release refuse and name rapid setup instead of working unguarded; status names the missing setup and prints no raw git error; check, bisect and doctor --history-only stay usable without it (the forge's runner case); after rapid setup the same clone works. |
| parallel-runner |  | The scenario runner runs scenarios concurrently: with -j 3, three scenarios that each take two seconds finish together in well under the six seconds a serial run needs, the results print in file order whatever order they finish in, each scenario has its own TMPDIR removed with the run, a failing scenario is named with its output tail and fails the run, and -j 1 still runs serially with the same verdicts; a failure is reported live and starts RAPID_TEST_ON_FAIL at once; with --verbose each scenario prints a progress line [n/total] the moment it ends, without it none. |
| parallel-suites |  | several suite runs at once on one machine, sharing TMPDIR: every run passes and none leaves a temp directory behind. |
| private-worktree | yes | a gate never runs in the caller's work tree: when no private work tree can be made (the temp directory is gone, as under a disk sweep), check --each and land refuse, and a push from a linked work tree (git exports GIT_DIR to the hook) leaves that work tree as it was; the caller's branch and files stay as they were; while a gate runs, its private work tree's root is kept fresh (a heartbeat), so a sweeper of idle work trees never takes it. |
| push-is-transport | yes | push-is-transport: a branch push runs no gate, so a branch holding a red commit reaches origin as it is, and the close, which tests the tree it pushes, refuses it with origin's dev untouched; rapid sync rebases locally and never pushes (origin's copy of the branch stays where it was); the branch goes to origin by a plain git push, and a refused push prints the remote's own reason. |
| runner-knobs |  | the scenario runner's knobs: --fast runs the scenarios marked fast alone, a FILTER word runs the scenarios whose name holds it, RAPID_TEST_JOBS sets how many run at once when -j does not, RAPID_TEST_ONLY runs the named scenarios alone, RAPID_TEST_FAIL_DIR receives the output of a failing scenario for the command RAPID_TEST_ON_FAIL starts, and a stale SCENARIOS.md stops the run. |
| safety-anchors |  | safety anchors stay forever: rapid branch writes the branch safety/v<series>/<number>.<kind>.<name>, an anchor commit on the fork point; a sync and a rename never move it (a rename adds the new name's anchor); a branch push carries it and a coworker sharing the branch takes origin's, a land pushes it with its atomic push, an offline land publishes it with rapid sync --dev; pre-push refuses deleting, moving or forging one, and the agent guard denies it even after a preflight. |
| seed-existing |  | seed an empty origin from existing history: main stays at the initial commit, dev arrives with every tag it carries, in one atomic push. |
| sequence-sync | yes | two branches in two worktrees land in sequence; the second, behind dev, is rebased by land and takes N+1. |
| session-fixture | yes | the session fixture (tests/run.sh, pytest-xdist style): under RAPID_TEST_FIXTURE mkrepo sets a repo up once per run and per setup input (actors, RAPID_/GIT_ environment, global git config) and copies it, so the copy is the repo setup makes (hooks active, main and dev seeded, the actor the first admin); mkrepo DIR origin copies the repo with its seeded bare origin at $T/origin.git, the remote pointing there; another actor gets its own fixture, and a set commit date or a non-empty directory builds afresh; a lock left by a dead builder makes mkrepo build without the fixture. |
| setup-main |  | setup never advances main and names the owner: setup writes the setup author as the first admin in .rapid/admins, the working copy's own file, never in the seed (an agent session setting up writes none); after setup, ten lands and setup again in a second clone (which names its runner as admin from git's user.email and user.name), main is still the root commit locally and on origin; a clone that checked out dev alone takes its main from origin, never from the tip of dev; a clone that checked out main alone takes its dev from origin, never from main; where no main exists anywhere, main is the seed of dev, and an origin that refuses the seed push is said so, the hooks and the local main staying. |
| setup | yes | setup on a fresh clone: hooks active, main and dev seeded, the human runner the first admin. A repository with no .rapid/conf gets one that says gates_full=none; rapid setup --require-test writes requirement_test=required at the first setup, under which a branch with no requirement file is refused at land; in a seeded repository the flag is refused. |
| smoke-lints |  | the cheap test and the lint runner: tests/smoke.sh passes on a tree whose shell files parse, whose CLI prints its help and whose lints pass, and fails naming the shell file that does not parse or the lints that fail, with what bash said; a bash that could not start (no process available) is said as that, never as a file that does not parse; lint/run.sh runs every lint of .rapid/lint and fails on any finding. |
| stale-branch | yes | a branch behind dev lands: land rebases it onto dev itself, behind a preflight ref, and takes N+1. |
| unmarked-red | yes | an unmarked red commit in a branch is named by check --each; a land runs no gate (batch-land-local), so the close tests the final tree, which is green. |
| vault |  | vault branches: rapid land writes the branch vault/v<series>/<name> on the branch's tip as it landed, in the land's atomic push, so every branch keeps a pointer to its start (safety/) and its end (vault/) after the branch itself is deleted; an offline land's vault ref is published by rapid sync --dev; pre-push refuses deleting or moving one and the agent guard denies it, preflight or not. |
| version-math | yes | version math is a pure function of the history: series and year rollover, table-driven, no clock read. |
