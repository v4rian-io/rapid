# Scenario matrix

Generated by tests/gen-scenarios.sh from each scenario's header; do not edit.
Run: `sh .rapid/tests/run.sh [--fast] [-j N] [FILTER]` (N at once; default RAPID_TEST_JOBS or every scenario at once). Fast subset: marked `fast`.

| Scenario | Fast | Verifies |
|---|---|---|
| parallel-runner |  | The scenario runner runs scenarios concurrently: with -j 3, three scenarios that each take two seconds finish together in well under the six seconds a serial run needs, the results print in file order whatever order they finish in, each scenario has its own TMPDIR removed with the run, a failing scenario is named with its output tail and fails the run, and -j 1 still runs serially with the same verdicts; a failure is reported live and starts RAPID_TEST_ON_FAIL at once; with --verbose each scenario prints a progress line [n/total] the moment it ends, without it none. |
| parallel-suites |  | several suite runs at once on one machine, sharing TMPDIR: every run passes and none leaves a temp directory behind. |
| runner-knobs |  | the scenario runner's knobs: --fast runs the scenarios marked fast alone, a FILTER word runs the scenarios whose name holds it, RAPID_TEST_JOBS sets how many run at once when -j does not, RAPID_TEST_ONLY runs the named scenarios alone, RAPID_TEST_FAIL_DIR receives the output of a failing scenario for the command RAPID_TEST_ON_FAIL starts, and a stale SCENARIOS.md stops the run. |
| session-fixture | yes | the session fixture (tests/run.sh, pytest-xdist style): under RAPID_TEST_FIXTURE mkrepo sets a repo up once per run and per setup input (actors, RAPID_/GIT_ environment, global git config) and copies it, so the copy is the repo setup makes (hooks active, main and dev seeded, the actor the first admin); mkrepo DIR origin copies the repo with its seeded bare origin at $T/origin.git, the remote pointing there; another actor gets its own fixture, and a set commit date or a non-empty directory builds afresh; a lock left by a dead builder makes mkrepo build without the fixture. |
