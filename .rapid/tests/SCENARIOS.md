# Scenario matrix

Generated by tests/gen-scenarios.sh from each scenario's header; do not edit.
Run: `sh .rapid/tests/run.sh [--fast] [-j N] [FILTER]` (N at once; default RAPID_TEST_JOBS or every scenario at once). Fast subset: marked `fast`.

| admin-policy |  | policy flips are the admins': rapid setup writes the setup author into .rapid/admins, the working copy's own file (excluded, never in the seed); a change to a policy file (.rapid/conf) must be its own [MODE] commit, touching only policy files, authored and committed by an admin listed in .rapid/admins. commit-msg, land and pre-push refuse a flip that is not [MODE], mixes other files, or comes from a non-admin; a [MODE] commit that flips nothing is refused; a flip forced onto dev past the hooks is flagged I4 by doctor, and one hidden in the tree of a hand-made merge over a clean branch commit is flagged I1 and refused at push (a merge adds nothing of its own). An admin's flip lands, and an admin can name another. | agent-session |  | an agent session is an agent whatever identity it exports: with CLAUDECODE or a variable conf agent_env names set, a release is refused, even under the admin's identity, while commits and lands pass. rapid doctor names rapid setup --agent until the guard is installed for Claude Code. |
| banned-and-kept |  | banned files and kept branches, for humans too: pre-commit refuses a staged secret, key, certificate, build output, node_modules, .env, archive or backup on any branch (an .env.example passes, deleting a banned file passes); land and a branch push refuse one committed past the hook. The close and the doctor print their progress live on stderr: one counted line per merge. |

| batch-join |  | a branch landing into a batch whose close is testing stops that test: the close exits without pushing and its gate is gone with everything it started, the branch lands, and the next close tests the new final tree and pushes it all; a gate that reads its input finds none; while a close publishes the batch a land refuses, and a marker left by a close that is gone is stale. |
| batch-land-local |  | batch-land-local: a plain rapid land always lands into the open batch: five branches land with no gate run and no push, offline; one rapid land gates the final tree and pushes it all in one push; a close with no batch open says so. |
| batch-land |  | batch landing: rapid land --batch lands each branch exactly as a single land does (its own merge, version tag and test record) but locally and without gates; rapid land gates the final dev tree once and pushes everything in one atomic push. When that gate fails the batch stays: dev, the tags and the branches are kept, the branch that broke the close is named, nothing is pushed (the pre-push guard refuses any push while the batch is open), and rapid land --prune is the rollback. |
| batch-one-push |  | batch-one-push: a batch is exactly one push. Opening a branch pushes nothing, a land pushes nothing, the pre-push guard refuses every push while the batch is open (dev, a landed branch, a new branch), and rapid land sends one atomic push holding dev, the tags, the safety and the vault branches. A failed close keeps the batch and names the branch that broke it among several; the fix lands as one more branch and the next close is the batch's one push. |
| batch-test-records |  | honest test records: a branch landed into a batch says Gates: deferred to the close of batch <id> and names its tree as Merge-Tree, never Tested-Tree, since no gate ran on it; the close runs gates_each on the own tree of every merge of the batch, all at once, records each result in the gate log of that merge, then records the one gate of the final tree on the last merge. doctor --history accepts exactly that: a batch with no passing close record is flagged I3 (and doctor --verify and the push refuse a deferred test record whose batch shows no close, running the full gate on the merge a close record names), a deferred test record under Tested-Tree is flagged I3, and a merge whose own tree fails gates_each stops the close by name. |
| branch-numbers |  | branch numbers: rapid branch names every branch pool/v<series>/n<N>.<kind>.<name>, N one more than any number known, never shared. The number is carried by the branch's safety anchor (safety/v<series>/n<N>.<kind>.<name>), which origin holds once the branch is pushed, so another clone counts past it; offline a clone still writes n<N>, and a branch whose number another clone published first takes the next free number at its land; a closed branch keeps its number in the creation order; a landed merge carries Branch-Number:; a branch made by hand takes the next number at land; a hand-made name reusing a number is refused at land and flagged I7. |
| branch-size | yes | a branch over max_commits is refused before anything changes: its last commit is refused at commit, and made past the hooks the branch is refused by land. |
| check-gate |  | rapid check runs one gate on the work tree and says how it ended: the fast gate by default, the gate --gate names otherwise; "pass" with exit 0, "fail" with exit 1 and the end of the gate's own output, "none" for a gate the conf leaves unset or sets to none. It lands nothing. |
| checked-by-dev |  | a branch is checked by dev's framework, never by its own copy: a branch that rewrites the message rules in its own .rapid still has a bad message refused at commit, at land and at push, by the framework committed on dev, which rapid keeps exported under the git dir for that purpose. |
| cli-usage |  | the CLI's usage contract: rapid -h and --help print the whole usage, opening with the product's positioning (a software development lifecycle tool), and exit 0; no verb and an unknown verb print it and exit 2; a verb's -h prints that verb's lines alone; an argument a verb does not know is refused by name with exit 2 and changes nothing. |
| cli |  | the CLI helps and reports: each verb answers -h with its own usage, status --json reports branch, version and branches, and doctor --fix repairs the hooks setting. |
| commit-audit |  | the deterministic commit audit (the required commit-audit status): commit-msg refuses a subject joined by 'and', 'with', 'plus', 'or', 'then', 'beside', '+' or ',', a [FIX] without Cause: then Fix:, a commit above max_commit_lines and a [NEW] or [FIX] that changes behaviour without touching a test path (the commit after a Red: commit excepted). A smelly commit made past the hook is named by rapid check --audit and --each, refused by land and pre-push, and flagged by I4. The forge's commit-audit job runs rapid check --audit with dev's checker, and under land_pr=required dev's ruleset requires it. |
| concurrent-clones |  | two clones land concurrently: the loser's atomic close push is refused with nothing half-published; land --prune puts its dev back, then sync and land succeed as N+1. |
| doctor-history | yes | doctor --history reports a planted untagged merge, a stray tag and a deleted requirement file by invariant id; --since the root still checks every merge. The checkpoint: a clean run records dev's tip in a per-clone note (in the git dir, untracked, no ref) and the next run checks in full only the merges after it; a failing run, --since and --history-only write no note; --all walks every merge; a recorded merge no longer on dev's first-parent line, changed tags, a changed conf or rapid code, or a broken note walk every merge and say why; over a 200-merge fixture the default run stays under 60 s. |
| dry-run |  | a dry run changes nothing: with origin's dev ahead, rapid land --dry-run and rapid release --dry-run leave local dev, its work tree and the release tags where they were, and say to sync first. |
| early-detection |  | detection at commit and at branch push: the commit that would push a branch past max_commits is refused before it is written (an amend passes); a branch's first commit carrying the placeholder requirement is refused; with gates_commit set a staged tree that fails it is refused at commit; a branch push above max_commits is refused (a red branch commit is transport: see push-is-transport). |
| exceptions |  | one command shows every exception: doctor --history (and --history-only) lists, by kind, the versions of the merges carrying Untested: (land copies it from the requirement) or Docs: none, and of the merges that ran no gate, while history stays ok. |
| fix-names-its-test |  | a [FIX] may name its existing test instead of touching a test path: with real test_paths, a [FIX] that changes behaviour only and carries 'Test: <test path>' naming a test its tree holds commits and lands; one naming a missing file is refused at commit, and made past the hook is refused by land; a [FIX] with neither a test path nor a Test: is refused with the trailer named. |
| forge-namespaces |  | the branch namespaces: anchors are branches safety/v<series>/<name> (an anchor commit on the fork point), landed tips branches vault/v<series>/<name>, so setup --remote's rapid-safety-lockdown, rapid-vault-readonly and rapid-branch-deletions rulesets (admins alone bypass) cover them, as the gh stub records; creating an anchor stays open to every lander, and pre-push refuses an anchor or a number key that names another branch. A forge that lets only admins delete branches keeps a landed or closed branch: the land and the close still succeed, status and doctor list it, and an admin's rapid branch --delete-landed removes it (never a branch not landed yet). |
| gate-log |  | the durable gate log: rapid land stores its one gate's command, exit code, duration and log tail (the value of every TOKEN, SECRET, KEY, PASSWORD or CREDENTIAL variable redacted) as a note on the merge under refs/notes/gates, pushed atomically with dev and the tag; a second clone's land merges origin's notes first, so the ref only grows; rapid doctor --verify shows the stored log beside the rerun; pre-push refuses deleting or rewriting the notes ref, and the agent guard refuses writing, rewriting or deleting it by hand. |
| gate-verify |  | gate test records are re-verified: a hand-built merge claiming Gates: pass over a failing tree is refused by pre-push (its fast gate is rerun, also when it carries a close note another clone wrote) and, planted past the hook, reported by doctor --verify with the test record it claimed; a dev push without the merge's version tag is refused; a release tag records its gate and tree. |
| install |  | install: rapid installs once per machine with no copy. install.sh clones rapid with its tags into RAPID_HOME (default ~/.rapid) and runs rapid setup --install, which links rapid into a bin directory of PATH (~/.local/bin) from wherever the clone stands, baks/ and .rapid-versions/ kept out of the clone's tree by its local exclude; a second run changes nothing; rapid runs through the link from any directory; with no bin directory on PATH the install is refused by name; a file that is no link to a rapid is never replaced; nothing is written outside the clone and the link. |
| land-body | yes | merge bodies and requirements say something: land refuses a requirement under three words, a body paragraph under three words and a list without an item of two words, and a body that sets a trailer land writes itself; a body's final paragraph of 'Key: value' lines becomes real trailers. |
| land-closes-batch |  | rapid land lands its branch and closes the open batch: the branches landed with --batch before it stayed local, the close tests the final tree once and one push carries every merge. With no batch open it is a batch of one, through the same path. Run again it redoes nothing: a close origin refused runs again from the landed branch, or from dev, without testing the same tree twice. rapid land --halt stops the close under test and keeps the batch, and says so when no close is under test. |
| land-integrity |  | land integrity: a coworker's commit on a shared branch is never discarded, the requirement and merge body must be real, a landed requirement is never edited or deleted, and an empty body file is refused by name. |
| land-local | yes | branch, three commits, land with no remote: I1-I4 and I8 hold, exit 0. requirement_test is optional by default: a branch opened with no -r, --test or --ticket stages no requirement file, commits with no placeholder in its way and lands with no Requirement: trailer; a test that is given is checked and recorded. |
| land-rebases | yes | land-rebases: four branches forked from the same dev land in one command (rapid land BRANCH...): land rebases each stale branch onto dev itself behind a preflight ref; the third conflicts with the first, so it is left exactly as it was, named with its conflicting file, land_on_conflict starts on it, and the exit is 4, while the second and the fourth still land. |
| land-remote |  | land with a remote: one atomic push carries dev, the tag and the branch deletion. |

| reland-resume |  | a re-land that hits a conflict keeps every offline land: three offline lands (the second naming the first with Fixes:) meet a conflicting online land; sync --dev stops, the plan survives, doctor reports it, --continue re-lands all three with Fixes: following the new sha; --abort keeps the rest as branches not landed yet and nothing is lost. |
| release-gate |  | a failing release gate leaves main and the tags unchanged, here and on origin; the gate is announced and its output is printed live on stderr, once. |
| release-merge |  | a release is a --no-ff merge of dev into main, "[MERGE] dev into main: <v>", made by the owner's rapid release: its second parent is the released dev tip, its tree that tip's, its body the branches landed since the last release, so git log --first-parent main lists the releases. pre-push refuses main moving to a dev commit, to a merge whose tree is not the released one and to a merge without the release subject; doctor flags a forged main (I5).
