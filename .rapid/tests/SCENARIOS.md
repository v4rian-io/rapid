# Scenario matrix

Generated by tests/gen-scenarios.sh from each scenario's header; do not edit.
Run: `sh .rapid/tests/run.sh [--fast] [-j N] [FILTER]` (N at once; default RAPID_TEST_JOBS or every scenario at once). Fast subset: marked `fast`.

| Scenario | Fast | Verifies |
|---|---|---|
| batch-land-local |  | batch-land-local: a plain rapid land always lands into the open batch: five branches land with no gate run and no push, offline; one rapid land gates the final tree and pushes it all in one push; a close with no batch open says so. |
| branch-numbers |  | branch numbers: rapid branch names every branch pool/v<series>/n<N>.<kind>.<name>, N one more than any number known, never shared. The number is carried by the branch's safety anchor (safety/v<series>/n<N>.<kind>.<name>), which origin holds once the branch is pushed, so another clone counts past it; offline a clone still writes n<N>, and a branch whose number another clone published first takes the next free number at its land; a closed branch keeps its number in the creation order; a landed merge carries Branch-Number:; a branch made by hand takes the next number at land; a hand-made name reusing a number is refused at land and flagged I7. |
| cli-usage |  | the CLI's usage contract: rapid -h and --help print the whole usage, opening with the product's positioning (a software development lifecycle tool), and exit 0; no verb and an unknown verb print it and exit 2; a verb's -h prints that verb's lines alone; an argument a verb does not know is refused by name with exit 2 and changes nothing. |
| cli |  | the CLI helps and reports: each verb answers -h with its own usage, status --json reports branch, version and branches, and doctor --fix repairs the hooks setting. |
| land-local | yes | branch, three commits, land with no remote: I1-I4 and I8 hold, exit 0. requirement_test is optional by default: a branch opened with no -r, --test or --ticket stages no requirement file, commits with no placeholder in its way and lands with no Requirement: trailer; a test that is given is checked and recorded. |
| no-setup-clone |  | a clone that never ran rapid setup says so: rapid branch, land, sync and release refuse and name rapid setup instead of working unguarded; status names the missing setup and prints no raw git error; check, bisect and doctor --history-only stay usable without it (the forge's runner case); after rapid setup the same clone works. |
| parallel-runner |  | The scenario runner runs scenarios concurrently: with -j 3, three scenarios that each take two seconds finish together in well under the six seconds a serial run needs, the results print in file order whatever order they finish in, each scenario has its own TMPDIR removed with the run, a failing scenario is named with its output tail and fails the run, and -j 1 still runs serially with the same verdicts; a failure is reported live and starts RAPID_TEST_ON_FAIL at once; with --verbose each scenario prints a progress line [n/total] the moment it ends, without it none. |
| parallel-suites |  | several suite runs at once on one machine, sharing TMPDIR: every run passes and none leaves a temp directory behind. |
| runner-knobs |  | the scenario runner's knobs: --fast runs the scenarios marked fast alone, a FILTER word runs the scenarios whose name holds it, RAPID_TEST_JOBS sets how many run at once when -j does not, RAPID_TEST_ONLY runs the named scenarios alone, RAPID_TEST_FAIL_DIR receives the output of a failing scenario for the command RAPID_TEST_ON_FAIL starts, and a stale SCENARIOS.md stops the run. |
| safety-anchors |  | safety anchors stay forever: rapid branch writes the branch safety/v<series>/<number>.<kind>.<name>, an anchor commit on the fork point; a sync and a rename never move it (a rename adds the new name's anchor); a branch push carries it and a coworker sharing the branch takes origin's, a land pushes it with its atomic push, an offline land publishes it with rapid sync --dev; pre-push refuses deleting, moving or forging one, and the agent guard denies it even after a preflight. |
| seed-existing |  | seed an empty origin from existing history: main stays at the initial commit, dev arrives with every tag it carries, in one atomic push. |
| session-fixture | yes | the session fixture (tests/run.sh, pytest-xdist style): under RAPID_TEST_FIXTURE mkrepo sets a repo up once per run and per setup input (actors, RAPID_/GIT_ environment, global git config) and copies it, so the copy is the repo setup makes (hooks active, main and dev seeded, the actor the first admin); mkrepo DIR origin copies the repo with its seeded bare origin at $T/origin.git, the remote pointing there; another actor gets its own fixture, and a set commit date or a non-empty directory builds afresh; a lock left by a dead builder makes mkrepo build without the fixture. |
| setup-main |  | setup never advances main and names the owner: setup writes the setup author as the first admin in .rapid/admins, the working copy's own file, never in the seed (an agent session setting up writes none); after setup, ten lands and setup again in a second clone (which names its runner as admin from git's user.email and user.name), main is still the root commit locally and on origin; a clone that checked out dev alone takes its main from origin, never from the tip of dev; a clone that checked out main alone takes its dev from origin, never from main; where no main exists anywhere, main is the seed of dev, and an origin that refuses the seed push is said so, the hooks and the local main staying. |
| setup | yes | setup on a fresh clone: hooks active, main and dev seeded, the human runner the first admin. A repository with no .rapid/conf gets one that says gates_full=none; rapid setup --require-test writes requirement_test=required at the first setup, under which a branch with no requirement file is refused at land; in a seeded repository the flag is refused. |
| smoke-lints |  | the cheap test and the lint runner: tests/smoke.sh passes on a tree whose shell files parse, whose CLI prints its help and whose lints pass, and fails naming the shell file that does not parse or the lints that fail, with what bash said; a bash that could not start (no process available) is said as that, never as a file that does not parse; lint/run.sh runs every lint of .rapid/lint and fails on any finding. |
| version-math | yes | version math is a pure function of the history: series and year rollover, table-driven, no clock read. |
